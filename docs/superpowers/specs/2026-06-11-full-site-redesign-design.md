# Full-site redesign: «Миграционный справочник»

**Дата:** 11 июня 2026  
**Статус:** согласовано на уровне визуального направления и структуры

## 1. Цель

Полностью переработать существующий миграционный SEO-портал в единую систему под брендом **«Миграционный справочник»**.

Главная бизнес-задача сайта — не немедленная продажа консультации. Сайт должен:

1. определить ситуацию и поисковый интент посетителя;
2. направить его в подходящий тематический кластер;
3. углубить в связанные статьи и интерактивные инструменты;
4. увеличить глубину просмотра, полезное время на сайте и возвраты;
5. предложить ИИ-помощника или консультацию только после получения пользователем самостоятельной пользы.

## 2. Визуальное направление

За основу берётся коммерческая ясность и композиционная система `prizyvanet.ru`, но не его контентная воронка и не буквальное оформление.

Сохраняем:

- крупную гротескную кириллическую типографику;
- светлый холодный фон и белые функциональные панели;
- тёмно-синий основной текст;
- насыщенный синий для навигации, хабов и инструментов;
- красный акцент для главных действий, срочных изменений и активных состояний;
- крупные скругления, ясные формы, высокую контрастность;
- плотную, но хорошо разделённую последовательность полезных блоков.

Не переносим:

- консультационную форму как главный элемент первого экрана;
- повторяющиеся агрессивные формы захвата;
- псевдогосударственные формулировки;
- декоративные элементы без информационной функции;
- чужой логотип, иллюстрации и тексты.

### Палитра

- `--background: #F4F6FA`
- `--surface: #FFFFFF`
- `--ink: #1F2C41`
- `--muted: #667287`
- `--primary: #02629F`
- `--primary-dark: #014B79`
- `--accent: #FF2E32`
- `--accent-dark: #D92327`
- `--border: #D8DEE7`
- `--info-soft: #EDF2FD`
- `--danger-soft: #FFF0F0`

Красный не используется как большой фоновый цвет обычных секций. Его назначение: основной CTA, важное обновление, ошибка, предупреждение и текущий пункт навигации.

### Типографика

Основной шрифт — **Golos Text Variable** с полной поддержкой кириллицы.

- Display/H1: 56–72 px на desktop, 38–44 px на mobile, 600–700.
- H2: 40–48 px, 600.
- H3: 28–34 px, 600.
- Основной текст: 18–20 px в статьях, 16–18 px в интерфейсах.
- Подписи и метаданные: 13–14 px, 500–600.
- Крупные заголовки получают отрицательный tracking и короткую длину строки.
- Статейный текст ограничивается примерно 68 символами в строке.

Шрифт подключается через локальный файл или `next/font`; внешний runtime-запрос к Google Fonts не нужен.

## 3. Информационная архитектура главной

Главная является SEO-хабом и навигатором по интентам.

### Порядок блоков

1. **Шапка и поиск**
   - бренд;
   - переходы в ВНЖ, РВП, гражданство, работу и документы;
   - заметный поиск по инструкциям;
   - мобильное меню.

2. **Hero с быстрым подбором маршрута**
   - H1 по главному кластеру «как переехать / легализоваться в России»;
   - дата актуальности;
   - краткое обещание результата;
   - первый вопрос сегментирующего квиза;
   - вторичный переход к каталогу материалов.

3. **Сигналы доверия**
   - дата актуальности;
   - нормативная база;
   - охват регионов;
   - бесплатный доступ без регистрации.

4. **Сегментация по жизненной ситуации**
   - семья в России;
   - работа и профессия;
   - учёба;
   - соотечественники и репатриация;
   - отсутствие специальных оснований.

5. **Главные SEO-кластеры**
   - ВНЖ как приоритетный кластер;
   - РВП;
   - гражданство;
   - работа и патент;
   - запреты и легальность.

6. **Изменения законодательства**
   - датированные карточки;
   - ссылка на подробный разбор;
   - источники и дата проверки.

7. **Интерактивные инструменты**
   - подбор статуса;
   - проверка документов;
   - ИИ-консультант;
   - парсер документов как дополнительный профессиональный инструмент.

8. **Популярные и рекомендуемые инструкции**
   - одна выделенная pillar-статья;
   - список связанных материалов;
   - динамическая перелинковка по кластерам.

9. **Поздний CTA**
   - сначала вопрос RAG-помощнику;
   - консультация специалиста предлагается только для индивидуального анализа.

10. **FAQ и компактный footer**
    - вопросы о назначении портала;
    - методология проверки;
    - правовые документы и дисклеймер.

### SEO-требования

- Один тематически точный `h1`.
- Последовательная иерархия `h2`/`h3`.
- Серверный HTML для всех индексируемых текстов и ссылок.
- Основная навигация не зависит от JavaScript.
- Перелинковка использует реальные ссылки, а не обработчики на `div`.
- Главная ссылается на каждый pillar-кластер.
- Датированные обновления содержат `time`.
- Добавляется JSON-LD для `WebSite`, `Organization`, `SearchAction` и хлебных крошек там, где применимо.

## 4. Шаблон SEO-статьи

Единый шаблон используется для pillar-, body- и long-tail-страниц.

### Структура

1. хлебные крошки;
2. тип материала и дата редакции;
3. H1 и лид;
4. метаданные: дата, время чтения, статус проверки;
5. блок «Короткий ответ»;
6. липкое содержание на desktop;
7. основная статья;
8. блоки источника и правового основания;
9. предупреждения и важные уточнения;
10. пошаговые блоки;
11. таблицы, списки документов и downloadable-материалы;
12. контекстная перелинковка «Следующий шаг»;
13. FAQ;
14. связанные статьи;
15. боковая колонка с актуальностью, инструментом и RAG;
16. консультация после основного материала или при сложном вопросе.

### MDX-компоненты

- `ArticleMeta`
- `QuickAnswer`
- `LegalSource`
- `Notice`
- `Warning`
- `Steps`
- `DocumentChecklist`
- `ComparisonTable`
- `RelatedGuide`
- `InlineToolBanner`
- `RagQuestion`
- `FaqAccordion`
- `ExpertReview`
- `ConsultationBanner`

FAQ работает без JavaScript через `details/summary` либо получает минимальное progressive enhancement.

## 5. Остальные шаблоны

### Кластерный хаб

Для `/pathways` и основных разделов ВНЖ, РВП, гражданства:

- краткое объяснение темы;
- карта вложенных материалов;
- выбор ситуации;
- сравнение оснований;
- изменения законодательства;
- рекомендуемый инструмент;
- последовательность дальнейших шагов.

### Инструмент

Для калькуляторов, проверки документов, парсера и ИИ:

- ясное название результата;
- краткое объяснение данных и ограничений;
- пошаговый интерфейс;
- прогресс и сохранение состояния в рамках сессии;
- контекстные ссылки на статьи;
- состояния loading, error, empty и success;
- лид-форма только после результата или при запросе помощи.

### Служебная правовая страница

Для проверки запрета и аналогичных страниц:

- высокая заметность рисков;
- точное разграничение официальной проверки и справочного материала;
- ссылки на государственные источники;
- явный дисклеймер;
- консультация как дополнительный, а не единственный выход.

## 6. Компонентная система

Обязательные общие компоненты:

- новая адаптивная шапка с поиском;
- `SectionHeading`;
- `PrimaryButton`, `SecondaryButton`, `TextLink`;
- карточка сегмента;
- карточка кластера;
- карточка статьи;
- карточка изменения закона;
- карточка инструмента;
- шаги и прогресс;
- поля формы и состояния валидации;
- alert/notice/source;
- accordion;
- поисковая выдача;
- RAG-панель;
- ненавязчивый floating-widget;
- footer.

Иконки — единый SVG-набор с одинаковой толщиной линий. Эмодзи запрещены. Уникальные тематические иллюстрации выполняются как собственные SVG.

## 7. RAG и контент

RAG используется для:

- формирования кратких ответов и FAQ из индексированной базы;
- проверки фактов и дат;
- выбора релевантных источников;
- выдачи связанных статей;
- ответов ИИ-консультанта с внутренними ссылками.

RAG не должен генерировать индексируемый основной текст во время клиентского рендера. Индексируемый контент хранится в MDX и проходит редакционную фиксацию.

Каждый юридически значимый факт получает:

- дату проверки;
- ссылку или название первоисточника;
- осторожную формулировку при региональной или ситуационной вариативности.

## 8. Доступность и адаптивность

- Контраст не ниже WCAG AA.
- Touch-target не меньше 44×44 px.
- Видимый `focus-visible`.
- Skip-link к основному содержимому.
- Корректная семантика `header`, `nav`, `main`, `article`, `aside`, `footer`.
- Анимации только через `transform` и `opacity`.
- `prefers-reduced-motion` отключает необязательное движение.
- Поддерживаемые контрольные ширины: 375, 768, 1024 и 1440 px.
- На мобильном содержание статьи становится раскрываемым блоком, боковая колонка перемещается после лида или статьи.

## 9. Анимация

Анимация сдержанная:

- последовательное появление hero;
- прогресс сегментирующего квиза;
- плавные состояния карточек и кнопок;
- раскрытие FAQ;
- простые SVG-линии маршрута;
- без бесконечного пульса, параллакса и тяжёлых scroll-сцен.

GSAP сохраняется только там, где он даёт измеримую пользу. Базовые состояния реализуются CSS.

## 10. Техническая реализация

- Сохраняется Next.js 16 App Router, React 19, Tailwind CSS 4 и MDX.
- Перед изменением API и соглашений используются локальные документы `node_modules/next/dist/docs/`.
- Серверные компоненты являются стандартом; client components применяются только для интерактивности.
- Главная разбивается на самостоятельные секции, а не остаётся одним большим client component.
- Шрифты подключаются по актуальной документации Next.js 16.
- Метаданные и structured data задаются на сервере.
- Существующие API лидов и консультанта сохраняются.
- Редизайн не меняет URL существующих индексируемых страниц.

## 11. Проверка

### Автоматически

- `npm run lint`
- `npm run build`
- проверка отсутствия битых внутренних ссылок;
- проверка heading hierarchy и landmark-элементов;
- тесты ключевых интерактивных состояний.

### Визуально

Проверяются:

- главная;
- хаб `/pathways`;
- одна pillar-статья;
- одна long-tail статья;
- каждый тип инструмента;
- lead/RAG/floating-widget;
- desktop и mobile.

### Критерии готовности

- все существующие страницы используют общую дизайн-систему;
- нет эмодзи и случайных иконографических стилей;
- консультация не доминирует до получения основной пользы;
- главная обеспечивает прямые пути ко всем основным SEO-кластерам;
- статья содержит понятный следующий шаг и связанные материалы;
- сборка и lint проходят без ошибок.
